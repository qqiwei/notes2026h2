Visualising the stack —— symmetric_trans.cpp

本文针对本目录下 symmetric_trans.cpp 的实际代码，给出其运行时栈/堆的可视化。

先来看一下我们实际的代码（关键部分）：

template <typename Promise> struct SymmetricTransFinalAwaiter {
  bool await_ready() const noexcept { return false; }
  std::coroutine_handle<>
  await_suspend(std::coroutine_handle<Promise> single_task_h) noexcept {
    auto task_handle = single_task_h.promise().task_handle_;
    return task_handle;              // 对称转移方向 2：single task → task
  }
  void await_resume() const noexcept { LOG_FUNCTION(); }
};

struct SyncTransTask {
  struct promise_type {
    std::coroutine_handle<> task_handle_ = nullptr;
    ...
    using final_awaiter = SymmetricTransFinalAwaiter<promise_type>;
    final_awaiter final_suspend() noexcept { return {}; }
    ...
  };

  std::coroutine_handle<promise_type> handle_;
  ~SyncTransTask() {
    LOG_FUNCTION();
    if (handle_)
      handle_.destroy();
  }

  struct awaiter {
    std::coroutine_handle<promise_type> handle_;
    bool await_ready() const noexcept { return false; }
    std::coroutine_handle<>
    await_suspend(std::coroutine_handle<> task_handle) noexcept {
      auto &promise = handle_.promise();
      promise.task_handle_ = task_handle;   // 对称转移方向 1：task → single task
      return handle_;
    }
    void await_resume() const noexcept { LOG_FUNCTION(); }
  };

  awaiter operator co_await() const noexcept { return awaiter{handle_}; }
};

SyncTransTask make_single_task() {
  return make_single_task_impl<SyncTransTask>(FUNCTION);
}

Task make_task(int count) {
  return make_task_impl<SyncTransTask>(FUNCTION, count, &make_single_task);
}

int main() {
  LOG_MSG("make task");
  auto task = make_task(3);
  TRACK_RESUME(task.handle_.resume());   // 直接 resume 启动，不参与循环
  return 0;
}

其中涉及的关键实体如下：

symmetric_trans.cpp 说明

make_single_task() → make_single_task_impl<SyncTransTask>（promise 类型 SyncTransTask） 每次循环创建并 co_await 的协程，frame 地址 0x0102d7f0
SyncTransTask::awaiter::await_suspend 返回 handle_（symmetric_trans.cpp:69-77） 对称转移方向 1：task → single task
SymmetricTransFinalAwaiter::await_suspend 返回 task_handle_（symmetric_trans.cpp:6-12） 对称转移方向 2：single task → task
main() 直接调用 task.handle_.resume() 启动协程，不参与循环

说明：coroutine 函数在编译时通常被拆成两部分——处理 coroutine frame 构造/返回值的 “ramp 函数” 与包含用户逻辑的 “coroutine body”。这里用 $resume 后缀指代 “coroutine body” 部分。后续在 co_await GetHandleAwaiter{}（coro.hpp:112）处 task 协程会捕获自己的 handle（0x0102d750），该 awaiter 的 await_suspend 返回 false，立即恢复，不产生新的栈帧。

现在 task 协程执行到 co_await single_task;（coro.hpp:116），将发生一次对称转移：

  • 调用 SyncTransTask::operator co_await() 返回 SyncTransTask::awaiter 对象；
  • task 协程挂起，调用 SyncTransTask::awaiter::await_suspend（symmetric_trans.cpp:69-77），把自身 handle 存入 single task 的 promise（[D1] save task's: 0x0102d750, trans to single task's: 0x0102d7f0）；
  • await_suspend 返回 single task 的 handle 0x0102d7f0，编译器将其编译为一次尾调用 / jmp：先弹出 task 的 $resume 帧，再跳转到 single task 的 $resume 帧。

因此 single task 被恢复后的栈/堆如下（栈帧数量与 task 首次启动时相同，没有增长）：

[D1] 对称转移：awaiter::await_suspend 把 task handle（0x0102d750）存入 single task 的 promise，返回 single task handle —— 尾调用弹出 task 帧，跳入 single task。

注意：这里的栈没有在 awaiter::await_suspend → single_task.resume() 之间层层嵌套帧，而是把 await_suspend 返回的 handle 当作尾调用目标，弹出当前帧后直接跳转。这正是对称转移的意义。

single task 协程随后同步执行完毕：make_single_task_impl 在 co_await GetHandleAwaiter{}（coro.hpp:100）处捕获自身 handle 并打印 single task's: 0x0102d7f0，co_return 后到达 closing curly brace，求值 co_await promise.final_suspend()。

SymmetricTransFinalAwaiter::await_suspend（symmetric_trans.cpp:6-12）挂起 single task，读取 promise 中保存的 task_handle_（[D2] single task's: 0x0102d7f0, trans to task's: 0x0102d750）并返回它——再次对称转移（尾调用）恢复 task 协程。single task 被恢复后的栈/堆如下：

可以看到，每轮循环结束时栈帧数与协程 frame 数与开始时完全一致，且不会增长。因此可以无限循环（如 count 传 1'000'000）而只使用恒定量的栈空间。

一个旁证：程序输出中每一轮迭代的 single task 地址都是同一个 0x0102d7f0——上一轮结束时其 frame 被销毁释放，下一轮创建的新 frame 复用了同一块内存，进一步说明所有资源都被及时回收、使用量恒定。
